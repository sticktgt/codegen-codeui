# codeui

`codeui` — веб-интерфейс и FastAPI-фасад для работы с локальными проектами через `codecollector`.

Приложение помогает выбрать проект, подключить требования, создать запрос на изменение кода, выполнить анализ, выбрать место изменения, запустить цепочку выполнения, просмотреть результат и вручную применить рабочую область к основному проекту.

`codeui` не индексирует код, не собирает контекст проекта, не генерирует код, не применяет изменения самостоятельно и не выполняет проверки проекта. Эти действия выполняет `codecollector`. `codeui` хранит пользовательские запросы на изменение, вызывает CLI `codecollector`, читает JSON-артефакты запусков и показывает их в интерфейсе.

## Возможности

- Отображение списка проектов из `codecollector`.
- Выбор активного проекта.
- Подключение нового проекта через подключение.
- Переиндексация проекта.
- Удаление проекта из `codecollector`.
- Подключение JSON-файла требований.
- Отображение дерева требований.
- Создание и редактирование запросов на изменение.
- Связь запросов на изменение с требованиями.
- Запуск анализа.
- Выбор рекомендованной или ручной цели изменения.
- Запуск цепочку выполнения.
- Отображение статуса запуска, шагов, проверок, diff, производственного кода, сгенерированного теста, исправления и рекомендательного разбора.
- Отображение плана применения.
- Применение последней рабочей области после ручного решения пользователя.
- Сохранение состояния интерфейса.
- Сохранение трассировки вызовов CLI.

## Основной сценарий

1. Пользователь открывает интерфейс.
2. Выбирает активный проект или подключает новый проект.
3. Подключает файл требований.
4. Выбирает требование.
5. Создаёт запрос на изменение.
6. Запускает анализ.
7. Проверяет рекомендованную операцию и цель.
8. Выбирает цель изменения.
9. Запускает цепочку выполнения.
10. Просматривает результат, проверки и diff.
11. Принимает решение о применении рабочей области.

Применение рабочей области выполняется отдельным действием. Цепочка выполнения не изменяет основной проект автоматически.

## Проекты

Активный проект отображается в верхней панели. Для проекта показываются:

- название;
- идентификатор;
- путь к корневой папке.

Список проектов читается из `codecollector`. В состоянии UI сохраняется выбранный проект.

### Подключение проекта

Форма подключения вызывает:

```bash
python -m codecollector projects onboard \
  --input-root /path/to/project_root \
  --project-name example_project \
  --full
```

Внутри ``input_root`` ожидается папка `src/`. Архитектурный файл `ARCHITECT.md` или `ARCHITECTURE.md` может находиться рядом с `src/`.

В форме задаются:

- название проекта;
- путь к папке проекта;
- режим полного перестроения индекса;
- пропуск LLM-обогащения архитектуры.

После успешного подключения проект выбирается активным.

### Переиндексация

Переиндексация вызывает:

```bash
python -m codecollector projects reindex \
  --project-id <project_id> \
  --full
```

Результат показывает количество файлов, модулей, символов, поисковых документов, embedded documents и режим синхронизации векторного поиска.

### Удаление проекта

Удаление проекта вызывает:

```bash
python -m codecollector projects delete --project-id <project_id>
```

После удаления список проектов обновляется. Если удалённый проект был активным, активный проект сбрасывается.

## Требования

`codeui` читает требования из JSON-файла. Поддерживаются два формата верхнего уровня:

```json
{
  "requirements": []
}
```

```json
[]
```

Требования отображаются иерархически по `parent_id`. Если отдельного заголовка нет, в списке используется начало `description`.

Основные поля требования:

- `id`;
- `project_id`;
- `type`;
- `status`;
- `priority`;
- `description`;
- `note`;
- `author`;
- `version`;
- `parent_id`;
- `verification_status`;
- `created_at`;
- `acceptance_criteria`;
- `tags`;
- `user_roles`;
- `trace_span`;
- `trace_start_char`;
- `trace_end_char`.

Требования в UI не редактируются. При создании запроса на изменение сохраняется снимок выбранных требований.

## Запросы на изменение

Запрос на изменение хранится как JSON-файл в `codeui`.

Основные поля:

- технический `cr_id`;
- пользовательский код вида `CR-000001`;
- `project_id`;
- связанные `requirement_ids`;
- снимок требований;
- title, description, constraints и notes;
- requested operation;
- insert scope;
- статус;
- session id;
- recommended target;
- selected target;
- связанные run ids;
- последний run id;
- идентификатор рабочей области;
- служебные raw-данные analyze, select target, run и apply.

Запрос можно редактировать до применения результата. При изменении исходных полей результаты анализа и последнего запуска сбрасываются.

Финальный статус — `applied`. В этом статусе запрос нельзя редактировать, удалять, анализировать, запускать повторно или применять повторно.

## Анализ

Анализ вызывает:

```bash
python -m codecollector sessions analyze
```

UI показывает:

- статус анализа;
- качество запроса;
- недостающую информацию;
- requested operation;
- insert scope;
- источник операции;
- уверенность и причину операции;
- recommended target;
- target role;
- уверенность и причину цели;
- признак необходимости ручной проверки;
- кандидатов;
- предупреждения;
- метрики использования и времени.

Статусы качества запроса:

- `processable` — запрос можно запускать при наличии выбранной или рекомендованной цели;
- `uncertain` — UI показывает предупреждение и позволяет продолжить после решения пользователя;
- `insufficient` — запуск блокируется до изменения запроса и повторного анализа.

## Операция, цель и область вставки

Для `replace_символ` выбранная цель является изменяемым символом.

Для `insert_after_символ` выбранный символ может быть:

- `anchor` — точка вставки;
- `parent_class` — класс, внутрь которого добавляется новый метод.

Поддерживаемые значения `insert_scope`:

- `module_body` — вставка top-level символа;
- `class_body` — вставка метода в класс.

## Запуск цепочку выполнения

Запуск вызывает:

```bash
python -m codecollector sessions generate
```

`codecollector` собирает контекст, вызывает `codegenerator`, применяет артефакт в промежуточную рабочую область, выполняет проверки, запускает исправления при необходимости, генерирует тест и формирует план применения.

`codeui` сохраняет связь запроса с run id и читает артефакты запусков из `.runs` проекта `codecollector`.

## Результат запуска

UI показывает:

- итоговый статус;
- selected target;
- target role;
- requested operation;
- итоговую операцию;
- insert scope;
- changed files;
- verification report;
- сгенерированный код;
- результат исправления;
- сгенерированный тест;
- разбор сгенерированного теста;
- diff;
- план применения;
- рекомендованные проверки;
- исключённые файлы;
- метрики использования.

Статус `ready_for_merge_review` означает готовность к ручной проверке. Он не означает автоматическое применение.

## Применение рабочей области

Применение последнего успешного результата вызывает:

```bash
python -m codecollector workspaces apply --workspace-id <workspace_id>
```

Перед применением пользователь проверяет статус запуска, diff, список изменённых файлов, исключённые файлы, сгенерированные тесты и рекомендованные команды проверки.

## Конфигурация

Основной файл настроек — `config.yaml`.

В конфигурации задаются:

- параметры приложения и HTTP-сервера;
- уровень логирования;
- путь к `codecollector`;
- команда Python и имя модуля для CLI-вызовов;
- лимит времени CLI-команд;
- пути к `.runs`, `.state` и `.workspaces` внутри `codecollector`;
- путь хранения запросов на изменение;
- источник требований;
- файл состояния UI;
- директория трассировки CLI-вызовов.

`data/ui_state.json` хранит выбранный проект, путь к файлу требований, выбранные требования и выбранный запрос на изменение.

## Trace CLI-вызовов

`codeui` логирует каждый вызов CLI `codecollector`: command, cwd, duration, код завершения, размер стандартный вывод и стандартный поток ошибок.

Если включён `command_trace`, стандартный вывод и стандартный поток ошибок сохраняются в `.trace/codecollector_cli`.

Файлы трассировки имеют вид:

```text
<timestamp>_<command-label>_<hash>.стандартный вывод.txt
<timestamp>_<command-label>_<hash>.стандартный поток ошибок.txt
```

Команда `projects list` не сохраняется в трассировке.

## Структура проекта

```text
codeui/
  README.md
  AGENTS.md
  pyproject.toml
  config.yaml
  data/
    requirements.json
    ui_state.json
    change_requests/
  codeui/
    main.py
    config.py
    dependencies.py
    errors.py
    logger.py
    api/
    schemas/
    services/
    static/
  tests/
```

Основные сервисы:

- `codeui/services/codecollector_client.py` вызывает CLI `codecollector`;
- `codeui/services/command_runner.py` запускает команды и сохраняет трассировку;
- `codeui/services/change_request_service.py` хранит запросы на изменение;
- `codeui/services/requirements_service.py` читает требования;
- `codeui/services/run_artifact_service.py` читает артефакты запусков;
- `codeui/services/run_view_service.py` строит compact view для UI;
- `codeui/services/ui_state_service.py` хранит состояние UI.

Основные клиентские файлы:

- `codeui/static/index.html`;
- `codeui/static/app.js`;
- `codeui/static/styles.css`.

## Запуск

```bash
python -m venv .venv
source .venv/bin/activate
pip install -e .
python -m codeui
```

По умолчанию UI доступен по адресу:

```text
http://127.0.0.1:8088/
```

## Проверки проекта

```bash
python -m compileall -q codeui
node --check codeui/static/app.js
python -m pytest -q
```

## Ограничения

- В приложении нет аутентификации и авторизации.
- Хранилище запросов на изменение и UI-состояния файловое.
- Требования читаются из JSON-файла и не редактируются в UI.
- Цепочка выполнения полностью выполняется в `codecollector`.
- Применение рабочей области выполняется только отдельным действием пользователя.
